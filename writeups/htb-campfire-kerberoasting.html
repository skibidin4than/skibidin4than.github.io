Hack The Box Campfire: Tracing a Kerberoasting Attack

A method-focused walkthrough of how Domain Controller and workstation logs are used to reconstruct a Kerberoasting attack.

DFIR Windows Event Logs Kerberoasting Prefetch MITRE ATT&CK

Campfire is a Hack The Box forensics challenge. We investigate Windows artifacts and Domain Controller event logs to reconstruct a Kerberoasting attack step by step, parsing the data with our own Python scripts.

01 Set up local parsing

Event logs are stored in the binary .evtx format, so we parse them locally with python-evtx and read each record as XML. We do this because it lets us filter on exact fields and check every finding on our own machine before we submit anything.

import os
import xml.etree.ElementTree as ET
from Evtx.Evtx import Evtx

02 Domain Controller security log

We start at the Domain Controller security log. Kerberoasting works by requesting Kerberos service tickets for Service Principal Names (SPNs), so we look for Event ID 4769, which records a service ticket (TGS) request (ATT&CK T1558.003 Kerberoasting).

For each 4769 record we read the event fields and keep two things apart: the account that requested the ticket, and the service the ticket was requested for. Mixing them up is an easy mistake. We confirm the workstation's IP address from the workstation authentication logs instead of assuming it.

03 PowerShell enumeration

Before roasting, an attacker usually maps Active Directory. We inspect the PowerShell Operational log on the workstation, looking through script block logs and execution entries for enumeration activity (ATT&CK T1059.001 PowerShell). We want to know what was run and where it was loaded from, so we rebuild the full path from the log entries.

04 Prefetch artifacts

Next we move to the workstation's file system and examine the Prefetch folder. Prefetch records that a program ran and when, so it helps us identify the tool used and its execution time.

We parse the Prefetch files with a parser such as PECmd and read the last-run value, which gives a precise UTC timestamp, so we never have to guess one.

We keep the sources separate. Domain Controller log times describe events on the Domain Controller, while Prefetch times describe execution on the workstation. Each question must be answered from the right source.

KEY TAKEAWAY

Different sources answer different questions: Domain Controller logs show who requested tickets, and workstation artifacts show what ran and when. Keep them separate, then join them on the timeline.
