Forensic Analysis: Tracking a Corporate Network Intrusion

A walkthrough of a 48-hour gateway firewall log that covers an intrusion from initial compromise to data exfiltration.

Network Forensics Blue Team Log Analysis MITRE ATT&CK

The Security Operations Center (SOC) detected abnormal traffic patterns on the corporate gateway firewall. The material is a 48-hour access log of all incoming and outgoing traffic. The incident covers the full life cycle of a modern attack: initial compromise, a covert communication channel, internal lateral movement, credential harvesting, and finally data exfiltration.

01 Initial access

Analysis points to a user workstation in the internal network zone as the starting point. This host began browsing suspicious external domains and downloading binary files, which triggered traffic anomalies in the security logs.

We start from the first anomalous host because it anchors the timeline. Every later event is read relative to it.

02 Command-and-control channel

After the compromise, the affected host showed consistent, periodic communication (beaconing) at regular intervals, on a non-standard port (ATT&CK T1571 Non-Standard Port). The traffic was encrypted (T1573 Encrypted Channel) and repeated throughout the monitoring period.

Regular timing matters because people browse irregularly, while malware checking in with a controller does not. This pattern is consistent with an attacker keeping remote access to the host.

03 Lateral movement and credential harvesting

Internal scanning: the attacker scanned for internal file-sharing services across several subnets (T1046 Network Service Discovery). We look at this because scanning is how an attacker maps the network before choosing targets.

Service ticket requests: the logs show Kerberos service ticket requests to the domain controller for the Service Principal Names (SPNs) of critical database and file services (T1558.003 Kerberoasting). This matters because service tickets can be requested by any domain user, so requests for many SPNs are a known sign of credential harvesting.

Critical asset access: according to the case summary, the attacker then accessed database and file servers and read confidential documents, financial records and personal data.

04 Data exfiltration

This phase is marked by a volume anomaly: outgoing data (bytes_tx) far exceeds incoming data (bytes_rx). Ordinary client traffic downloads more than it uploads, so a reversal of that ratio stands out. The attacker used standard command-line utilities wrapped in HTTPS to stage and send the stolen files to an external server.

05 Anti-forensics

Before the log period ended there were attempts to run log-clearing scripts and remote command execution to erase traces on the targeted systems (T1070 Indicator Removal). Clearing logs is typically one of the last things an attacker does, so it supports placing this at the end of the timeline.

06 How to approach the log yourself

Filter external traffic anomalies: compare legitimate business traffic (cloud services, collaboration tools, code repositories) with external connections that use unusual ports or administrative utilities.

Analyse byte ratios: find sessions where the volume sent outward (bytes_tx) suddenly spikes.

Correlate the timeline: match the period right after confidential files were read on internal servers with outgoing sessions to external IP addresses.

KEY TAKEAWAY

An intrusion is a chain, not a single event. Following the timeline stage by stage and matching each stage to what the logs show turns scattered anomalies into one story.
