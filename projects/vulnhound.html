01 What it does

VulnHound is a private, modular bug bounty tool. It runs one check at a time, twenty-eight modules, and saves every finding as structured JSON.

The terminal shows a short summary only. Findings live in files, grouped by category, with severity, confidence, and status.

It was built for one target first, then made generic. Per-program profiles decide which modules are allowed, so the same tool can hunt on other programs by switching profiles.

Nothing is submitted automatically. A candidate is a lead, not a bug, until a human validates it.

02 The checks

  • idor, one account reading or changing another account's resource.
  • webhook, SSRF through webhook URLs that resolve to private IPs.
  • xss, reflected cross-site scripting, probed with unique markers.
  • limit, bypass of download limits and link expiry.
  • privesc, free to Pro privilege escalation.
  • session, session handling, tampered tokens, and logout invalidation.
  • massassign, extra fields smuggled into update requests.
  • disclosure, sensitive files and endpoints left public.
  • storedxss, payloads stored in a field and executed on view.
  • redirect, open redirects in URL parameters.
  • preview, SSRF through link preview fetching.
  • authbypass, protected pages reached without a valid session.
  • cors, cross-origin policies that actually leak data.
  • jssecrets, API keys, tokens and credentials leaked in JavaScript.
  • sqli, SQL injection, error, boolean and time-based, read-only payloads.
  • ssti, server-side template injection.
  • lfi, local file inclusion and path traversal.
  • jwt, weak JSON Web Tokens: alg none, missing signature, missing expiry.
  • graphql, GraphQL introspection left open.
  • apidiscovery, API endpoints that leak data.
  • takeover, subdomain takeover fingerprints.
  • headers, missing or weak security headers.
  • bruteforce, login endpoints that never lock out, show a captcha, or rate-limit.
  • csrf, state-changing endpoints missing Origin, Referer, or token protection.
  • graphql_idor, the same GraphQL query as the owner, as another user, and with no session, responses compared.
  • xxe, XML request bodies parsed with external entities enabled.

The scan command runs the whole hunt from one URL, no profiles needed, with a built-in crawler. Deep mode validates a session, crawls behind a login, and auto-discovers IDOR and XSS targets. report turns a validated finding into a redacted draft, and retest checks whether an old finding is still there.

04 Rules

Private and not open source. There is no download link and no repository link.

Only in-scope targets, only your own accounts, and slow by design, with a delay between requests.

Scanner output is never submitted as a report. One vulnerability per report, validated by hand first.

Finding details stay private until triaged and cleared for disclosure.

05 Changelog

  • v1.4.1, 27 Nov 2026, deep mode: validate a session, crawl behind a login, auto-discover IDOR and XSS targets.
  • v1.4.0, Nov 2026, twenty-eight modules: bruteforce, csrf, graphql_idor and xxe join the checks.
  • v1.0.5, 23 Nov 2026, one-line skip summaries: sqli, ssti and lfi no longer print a line per skipped endpoint.
  • v1.0.4, 22 Nov 2026, jssecrets stops retrying dead third-party scripts and fetches each script once per run.
  • v1.0.3, 22 Nov 2026, live progress display: per-module progress and a request counter in background logs.
  • v1.0.1, 22 Nov 2026, automatic retry with backoff on 429 and 5xx: honours Retry-After, backs off exponentially, slows down adaptively after rate limits.
  • headers, 22 Nov 2026, security-header audit: HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy.
  • v1.0.0, 22 Nov 2026, the scan command (no JSON profiles), a same-origin crawler, and seven new checks: sqli, ssti, lfi, jwt, graphql, apidiscovery, takeover.
